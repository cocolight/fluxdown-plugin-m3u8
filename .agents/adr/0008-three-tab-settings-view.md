# 设置页改三个页签，去掉「专业设置」开关

> **本记录已被 [0009](0009-settings-host-form-only.md) 取代。** 以下是当时的判断与理由，保留作历史依据；
> 现行做法是「删自定义视图、设置面 = 宿主自动生成的表单」。

- 状态：已被 [0009](0009-settings-host-form-only.md) 取代
- 日期：2026-11-01
- 决策者：fluxdown-plugin-m3u8 维护者

## 背景

0007 落地后，设置页是「一页常用 + 一个『显示专业设置』开关展开另外 16 项」。三个问题：

1. **多一次操作**：想改「内嵌跟进几层」得先找到并打开开关，改完还留在展开状态。
2. **开关与参数混排**：基础页里既有开关（转 MP4、纯音频）也有选择框（画质、独立音轨），
   用户无法形成「这一页只看开关」的预期。
3. **`expertMode` 本身是一个设置项**，却只影响界面 —— 它出现在宿主的「基础设置」表单里，
   是个对下载毫无作用的条目，也让它占了 manifest 一个位置。

引擎侧的限制没有变化，仍是 0007 记录的那条：`SettingField` 是 `deny_unknown_fields`，
没有 `group` / `section` / `advanced`，宿主表单无法折叠。所以分区只能继续做在插件视图里。

## 决策

1. **视图改为三个页签**，按「用户想干什么」切分，不按代码模块：

   | 页签 | 判据 | 项数 |
   |---|---|---|
   | 基础设置 | 打开/关掉就完成，不需要输入任何值 | 11（全部是开关） |
   | 参数设置 | 要填值或选档位 | 14 |
   | 去广告设置 | 模式 + 预设 + 规则文本，三者互相牵连 | 2 |

2. **删除 `expertMode` 设置项**（manifest、`lib/settings.ts`、视图一并去掉）。页签选择只存视图
   state，**不落库**：它是「此刻浏览到哪」，不是配置。每次打开都从「基础设置」开始。
3. **`tabs` 只当标签条用**。官方《视图》参考写明 `tabs` 的 `children?: never` ——「只绘制标签条，
   所选 `value` 对应的内容由你自己渲染」。所以内容由 `state.tab` 决定渲染哪一组，不是把三组
   塞进 `tabs` 里由引擎切换。
4. **草稿留在 state 里，切页签不重建**。否则在参数页改几项、回基础页再改开关，保存时只剩最后一页的改动。

## 后果

- 正面：少一次「先展开」的操作；基础页语义单一（只有开关），能一句话说清；manifest 少一个与下载无关的条目。
- 负面，四条：
  1. **每个页签只渲染自己那组，另两组在树上不存在**。`tests/ui.mjs` 的「页面 key 覆盖 manifest」断言
     改为**遍历三个页签求和**，否则一页的断言天然看不到另外两页。
  2. **页签选择不持久**：用户每次打开都回到基础页。若日后要求「记住上次位置」，就得重新加一个界面设置项 ——
     那正是本次删掉的东西，需要重新权衡。
  3. **视图仍硬编码 27 个 key 与四个 `select` 的 options**。manifest 改名而视图没跟上，用户保存会收到
     「未知设置项」。由「三个页签求和覆盖 manifest」与「select 值必须在 options 内（按页走访）」两条断言顶住。
  4. 视图体积基本不变（`dist/main.js` 27627 → 27643 字节）：少一个开关与一段说明，多一个 `tabs` 节点。
  5. **视图 id 仍是 `ad-rules`**，而标题已是「插件设置」。不改 id 是因为宿主可能按 id 记视图状态，
     改名只换来整洁，代价是可能重置用户那边的记录 —— 名字与内容不符这件事写在代码注释与本节里。
- 门禁：`tests/ui.mjs` 43 → 48 项。新增 10 条页签断言（标签齐全与默认页、`items` 合法、基础页只有开关、
     参数项不落基础页、参数页无开关、去广告页自成一组、受控写回、未知页签回落、切页不丢草稿、三页求和覆盖 manifest），
     删除 6 条两档断言。
- 变异自检两处：① 去掉 `state.tab = normTab(ev.value)` → 6 项失败（页签失控，`openOn` 直接抛错）；
  ② 视图里把 `rangeCapKb` 写成 `rangeCapKB` → 2 项失败，报「manifest 有、三个页签都没有：`rangeCapKb`」。

## 备选方案

- **保留两档 + 加页签**：两套机制叠在一起，用户要同时理解「展开」和「切页」，复杂度更高。
- **把页签选择也存成设置项**（如 `uiTab`）：能记住位置，但等于把刚删掉的 `expertMode` 换个名字放回来。
- **只做「开关 / 参数」两页，去广告留在参数页**：去广告那组自带预设按钮与即时校验，与普通参数项不是一类东西，
  混在一起会让「参数设置」这一页变得不整齐。
