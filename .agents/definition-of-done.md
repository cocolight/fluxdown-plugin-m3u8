# 完成定义（Definition of Done）

功能是否算「完成」，以以下条件**同时满足**为准。本文件是 `AGENTS.md` §5 的详细版。

## 通用清单

- [ ] `ROADMAP.md` 中该行「验收标准」全部满足
- [ ] 新增或更新了对应测试，五层测试全量通过且符合测试质量基线
- [ ] 类型检查与格式检查通过
- [ ] 未引入无关改动（无顺手重构 / 格式化噪声）
- [ ] 相关文档（README / AGENTS / architecture / ADR / CHANGELOG）同步更新且符合写作纪律（AGENTS.md §4 第 13 条）
- [ ] `CHANGELOG.md` 的 `[Unreleased]` 已记录本次改动
- [ ] `ROADMAP.md` 状态更新为 `done`

## 按类型的差异

| type | 额外要求 |
|------|----------|
| `feat` | 必须新增测试；影响用户可见行为的，同步 `docs/settings.md` 或 README |
| `fix` | 必须新增能复现原缺陷的回归测试 |
| `docs` | 无需测试，但链接与示例须可用 |
| `chore` / `ci` | 不得降低既有门禁强度 |

## 测试质量基线

测试在场不等于测试有效。新增或修改的测试须同时满足：

- 断言行为而非实现：断言可观察行为（返回值、抛错、日志、宿主调用序列），不断言内部实现细节。重构实现而不改变行为时，测试不应变红。
- 测试名说清场景：名称回答「什么条件下做什么、期望什么」。不用 `test_ok`、`case1` 这类无信息名称。
- 拒绝空转断言：每个测试至少一条可能失败的断言。恒真断言、只断言类型或常量不算有效检查。
- **变异自检**：新增或修改断言后，故意破坏对应实现，确认断言会红，再恢复。没红过的断言视为未验证。

### 本项目特有约束

- `tests/legacy/` 是 v1.8.0 的冻结基线，**任何情况下不得修改**，包括「只是顺手统一风格」。
- 有意改变的行为写进 `contract` / `intercept` / `postprocess` / `ui`，**不得**通过修改基线或删除 `diverges` 声明来抹平 parity 差异。
- `diverges` 声明必须带具体理由；比对器会报「豁免过期」，不要把它当长期免检牌照。
- parity 里声明差异的场景若后来行为又变回去，属于回归，须查明原因而不是删声明。

## 禁止的「完成」信号（伪完成）

- 声称「测试已通过」但未实际运行命令。
- 用 `skip` / 注释掉断言 / 放宽比较让测试变绿。
- 用恒真断言或空转测试凑数，测试全绿但不检查任何行为。
- 为通过检查而放宽类型检查、lint、CI、hook 配置。
- 只改代码不改测试，或只改测试不改代码来掩盖问题。
- 把 `validate` 的 `elevated` 风险等级说成失败或缺陷（它由 `auth` + `ffmpeg` 权限决定，属预期）。
