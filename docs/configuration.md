> 插件：**M3U8 发现与变体解析器** · 版本 **1.8.0**
> 配置入口：**FluxDown → 设置 → 扩展 → 插件 → M3U8 发现与变体解析器**

## 一、作用域

### 目标站点主机 `targetHosts`

- **作用**：划定生效范围 —— 只解析这些网站的**播放页**。
- **怎么配**：只填**域名**，多个用英文逗号分隔；不带 `http://`、不带路径。
- **效果**：命中该域名及其子域名（填 `example.com` 会一并匹配 `video.example.com`）的播放页被解析；**粘贴的 `.m3u8` 直链不受此项限制、始终处理**。**留空 = 不处理任何页面**，此时插件只对直链生效。
- **示例**：`example.com, video.example.com, maccms.example.org`
  - 想覆盖某站全部子域，只填主域即可：`example.com`。

## 二、反爬站处理

### 自动通过防抓页校验 `solveChallenge`

- **作用**：自动通过站点设的「安全检查」中转页。
- **怎么配**：开关，默认开；遇到这类站点无需手动干预。
- **效果**：命中中转页时自动通过并**重新访问同一地址**，直达真实页面；**处理不了则退回原有行为**（放行或报错），不会比关闭更差。
- **示例**：打开站点先跳到「安全检查」页 → 插件自动通过，照常解析出播放列表。

### 跟随页面内嵌播放器 `followIframe`

- **作用**：从内嵌播放器页面取出 m3u8。
- **怎么配**：开关，默认开。
- **效果**：**只在页面里确实没有 m3u8 时才触发** —— 取出内嵌播放地址并跟进解析，抓取时带上 `Referer`；跟不到则退回原有行为。
- **示例**：详情页只有 `<iframe src="/vod-play/11076-1-1?iframe=1">` → 跟进该地址，在播放页取到 `master.m3u8`。

### 跟随内嵌播放器的最大层数 `iframeMaxFollow`

- **作用**：给内嵌跟进设深度上限，避免层层嵌套放大请求。
- **怎么配**：数字 1–3，默认 1。
- **效果**：1 = 只跟一层（覆盖绝大多数站点）；目标站把播放器套了两三层时调到 2 或 3；超出层数即停止。
- **示例**：站点结构为 `详情页 → iframe A → iframe B → 播放页`，需至少 2 层。

### 识别页面里的 DASH 清单 `detectDash`

- **作用**：页面里没有 m3u8、但有 DASH 清单（`.mpd`）时，自动取出该地址交给核心的 DASH 引擎下载。
- **怎么配**：开关，默认开。**无需额外配置** —— 直接粘贴的 `.mpd` 链接不受此项限制、始终处理。
- **效果**：**只在找不到 m3u8 时才兜底生效** —— 页面同时提供 m3u8 与 `.mpd` 时仍优先用 m3u8（保持原有行为）。插件**只交出地址，不解析清单内容**：分片、表征（Representation）选择、`SegmentBase` 等一律由核心 DASH 引擎处理。抠不到任何清单时照旧放行，不会比关闭更差。
- **示例**：某页面的播放器用 DASH 流（源码里只有 `.../manifest.mpd`）→ 开启后自动识别并把该地址交给核心，成功下载。

> 反爬站处理只覆盖**可自动通过**的形态。遇到**验证码 / 浏览器指纹**型站点请改用 yt-dlp 委派或浏览器扩展捕获 —— 插件沙箱既无 DOM 也无 JS 执行环境。

## 三、剧集与批量下载

### 识别剧集页并弹出选集 `detectSeries`

- **作用**：让多集页面在提交后先弹出选集窗口，一次勾选多集批量下载。
- **怎么配**：开关，默认开。**只影响播放页**，粘贴的 `.m3u8` 直链不受影响。
- **效果**：识别到多集信号（多集各自的 m3u8，或一批同构的分集链接）时，把「一页 N 集」作为**清单**返回，由 **FluxDown 引擎**自动建立任务组。判定只认强信号，**单视频页不会被误判**；关闭后恢复为「只解析当前看到的这一条」。
- **示例**：某站 `/vodplay/11076-1-1.html` ~ `-1-24.html` → 提交其中一集后弹出 24 项勾选框。

### 判定为剧集的最少条目数 `manifestMinItems`

- **作用**：滤掉「上一集 / 下一集」这类只有两三条链接的页面，降低误判。
- **怎么配**：数字 2–50，默认 3。**只在「页面没有 m3u8、只有一批分集链接」时生效** —— 链接按形态聚成一簇后，条目数达到此值才判为剧集页。
- **效果**：簇大小不够即不判剧集，正常解析当前集。**页面内直接出现多个分集 m3u8 时不看此项**（该路径按「质量折叠」判组）。
- **示例**：页面只有「上一集 / 下一集」两条链接 → 簇大小 2 < 3 → 不判剧集。

### 选集窗口最多列出的条目数 `manifestMaxItems`

- **作用**：给选集框的展示数量设上限，避免条目过多时过载。
- **怎么配**：数字 1–1000，默认 200。
- **效果**：超出的条目**不会列出，也无法勾选**（引擎自身另有 1000 条硬上限）。
- **示例**：长番 500 集、此项设为 200 → 选集框只列前 200 集。

### 自定义剧集链接正则 `episodeLinkPattern`

- **作用**：内置识别在个别站点不适用时，自定义「哪些链接算一集」。
- **怎么配**：填**不带定界斜杠**的 JS 正则原文（即 `new RegExp(...)` 的源码）；匹配时**忽略大小写**。留空用内置规则；**非法正则会被告警并忽略**（不中断解析）。
- **效果**：只有命中该正则的链接才参与剧集聚类与选集的链接簇判定。
- **示例**：站点用 `/vodplay/1-1-3.html` 表示第 1 季第 3 集 → 填 `vodplay/\d+-\d+-\d+\.html`；若用 `/episode/12/` → 填 `episode/\d+`（写 `\/episode\/\d+\/` 亦可，转义斜杠无害）。

## 四、画质与编码

### 偏好画质 `preferResolution`

- **作用**：决定弹画质框时**默认选中**哪一档。
- **怎么配**：下拉选择 `best` / `1080` / `720` / `480` / `360`，默认 `best`（最高码率）。
- **效果**：按变体**高度**比较 —— 在「不高于所选档位」的变体里取最高；若源里所有变体都高于所选档，则退到最低那档（保证总能选中一个）。源里未写分辨率时按最高码率选。**只影响默认选中项，不隐藏其他画质**。
- **示例**：源含 1080/720/480 → 选 `720` 默认落在 720p；源只有 2160/1440 而选 `720` → 退到 1440。

### 偏好视频编码 `preferCodec`

- **作用**：在候选变体里优先挑某种编码。
- **怎么配**：下拉 `auto`（默认）/ `avc`(H.264) / `hevc`(H.265) / `av01`(AV1) / `vp9`，默认 `auto`。
- **效果**：源里存在该编码的变体时优先在其中选；**一档都没有则回退全部变体**（不会选不到）。同样**不隐藏**其他变体。
- **示例**：源同时提供 HEVC 与 H.264 的 1080p → 选 `hevc` 默认选中 HEVC 那档。

### 自动选择 `autoPick`

- **作用**：决定提交链接后是弹画质框还是直接下载。
- **怎么配**：开关，默认关。
- **效果**：开 = 按「偏好画质 + 偏好编码」直接选定并开始下载，**不弹框**；关 = 先弹画质框列出全部变体供手选（默认选中项按偏好算）。
- **示例**：批量下载剧集时开启，避免每集都弹一次框。

## 五、音轨

### 音视频分离 `separateAudio`

- **作用**：控制是否把独立音轨拆出来作为 `audioUrl` 返回。
- **怎么配**：下拉 `auto`（默认）/ `on` / `off`。
- **效果**：
  - `auto` —— 只在源**明确是纯视频**或已把音轨单列（`#EXT-X-MEDIA:TYPE=AUDIO`）时才分离，避免音视频合一的流被拆出第二条音轨；
  - `on` —— 只要源提供独立音轨就分离；
  - `off` —— 从不分离。

  返回 `audioUrl` 后由 **FluxDown 核心自动合并**为单文件，插件不重复合并。
- **示例**：fMP4 式 HLS（视频流无声音、音轨单列）用 `auto` 即可自动配对。

### 音轨语言偏好 `audioLang`

- **作用**：多音轨时优先选哪条语言。
- **怎么配**：填语言标记，如 `zh` / `zh-CN` / `ja` / `en`。留空 = 按 `DEFAULT` / `AUTOSELECT` 选默认轨。
- **效果**：按变体 `LANGUAGE` 属性匹配；**未命中会回退默认轨并写日志**（不会导致失败）。
- **示例**：源含 `zh-CN`、`ja` 两条音轨 → 填 `zh` 选中 `zh-CN` 那条。

### 纯音频提取 `audioOnly`

- **作用**：音乐 / 播客场景，只下载独立音轨。
- **怎么配**：开关，默认关。
- **效果**：仅当源提供独立音轨（`#EXT-X-MEDIA:AUDIO` 或纯音频变体）时可用；**源里没有独立音轨时任务明确报错**，不会静默下载整个视频（音视频合一的 TS 在下载层无法分离音轨）。
- **示例**：某电台源把音频单列为 `audio/zh.m3u8` → 开启后只下这条音轨。

### 附：源里的写法与插件行为

| 源里的写法 | 插件行为 |
| --- | --- |
| `#EXT-X-MEDIA:TYPE=AUDIO,...,URI="audio/zh.m3u8"` | 按变体的 `AUDIO="组名"` 匹配音频组，选轨后作为 `audioUrl` 返回 |
| `#EXT-X-STREAM-INF:...,CODECS="avc1.640028"`（只有视频编码） | 判定为纯视频流 → 自动配上音轨 |
| `#EXT-X-STREAM-INF:...,CODECS="mp4a.40.2"`（只有音频编码） | 判定为纯音频变体 → 从画质列表移出，作为音轨来源 |
| `#EXT-X-STREAM-INF:...,CODECS="avc1.640028,mp4a.40.2"` | 判定为音视频合一 → **不分离**（避免拆出第二条音轨） |

选轨顺序：`AUDIO` 组收敛 → 「音轨语言偏好」按 `LANGUAGE` 匹配 → `DEFAULT=YES` → `AUTOSELECT=YES` → 第一条。

## 六、命名

### 命名模板 `nameTemplate`

- **作用**：控制插件**建议**的成品文件名格式。
- **怎么配**：可用占位符 `{title}` `{res}` `{lang}` `{host}` `{date}`；未知占位符会被清掉。默认 `{title} {host}`。
- **效果**：`{title}` 由插件推导（页面标题 → 上层 ID 目录 → 文件名，剔除 `index`/`playlist`/`master` 这类通用名）；填 `{title}` 单独一项 = **不加域名后缀**；留空同默认。注意：**弹画质框的手选模式下插件通常拿不到文件名**，最终名由核心决定（详见[附录](#附录文件名机制)）。
- **示例**：`{title} {date}` → `剧名 20261001`；`{title} {res} {host}` → `剧名 1920x1080 example.com`。

## 七、登录与请求头

### 登录凭据 `authCookie`

- **作用**：给「登录后才给 m3u8」的站点提供凭据。
- **怎么配**：点设置项旁的**「复制取 Cookie 的脚本」**按钮 → 在浏览器打开该站点、按 <kbd>F12</kbd> → 控制台粘贴执行 → 把打印出的内容粘回本框。也支持手写。
- **效果**：插件把内容规范化后交给 **FluxDown 持久化**（不落在插件自己的存储里），此后抓取**播放列表与分片**都会带上。**只在凭据登记站点与其同源时才注入**，不会跟着 CDN 主机发出去。
- **示例**（四种写法任选其一）：

| 你粘贴的内容 | 结果 |
| --- | --- |
| `SID=abc; uid=7` | 作为 `Cookie` 头注入 |
| `bearer:eyJhbGci…` 或 `token eyJhbGci…` | `Authorization: Bearer eyJhbGci…` |
| `basic:用户名:密码` | `Authorization: Basic …` |
| 多行 `键: 值`（如 `Cookie: …` / `X-Token: …`） | 逐条注入 |

> 登录入口**不实现任何站点特有的登录协议**（不做二维码轮询、不做 OAuth 跳转），因此对任何站点都能用，代价是需要手动取一次凭据。

### 自定义 User-Agent `userAgent`

- **作用**：覆盖请求 UA。部分站点会按 UA 返回不同的 playlist（移动端 / 桌面端）。
- **怎么配**：填完整 UA 字符串。留空 = 用 FluxDown 默认 UA。
- **效果**：作用于插件发出的所有抓取请求，并随返回值下发给下载链路；抓 playlist 与抓分片用**同一套头**。
- **示例**：`Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15`

### 额外请求头 `extraHeadersRaw`

- **作用**：手工追加任意请求头（如 `X-Requested-With`、站点自定义令牌）。
- **怎么配**：**每行一条 `Key: Value`**；以 `#` 开头的行视为注释。
- **效果**：同时作用于**抓 playlist 与抓分片**。**显式优先** —— 同名头会覆盖插件自动推导的 `Referer`/`Origin`。无需在此重复写 `Cookie`（登录凭据已由插件自动携带）。
- **示例**：

```
# 这是注释
X-Requested-With: XMLHttpRequest
X-Play-Token: 3f9a…
```

## 八、下载行为

### 防盗链/签名直链 `ephemeral`

- **作用**：应对一次性 / 带签名、被探测一次即作废的直链。
- **怎么配**：开关，默认关。
- **效果**：开启后**跳过元数据探测**，避免把签名链接提前用掉；恢复下载时**重新解析**获取新链接。
- **示例**：带 `?sign=…&expires=…` 的直链，开启后可直接下载。

### 启用 yt-dlp 委派 `useYtdlp`

- **作用**：把整个解析交给 yt-dlp，适合 m3u8 藏在 JS / 加密 JSON 里、原生正则抠不出的站点。
- **怎么配**：开关，默认关。**需先在「设置 → 扩展 → 组件」安装 yt-dlp**。
- **效果**：开启后链接直接交给 yt-dlp 抽取直链，插件不再走自己的解析。
- **示例**：SPA 站点的播放地址由前端接口动态下发时使用。

### 抓到 HTML 时用 yt-dlp 兜底 `htmlFallbackYtdlp`

- **作用**：抓 playlist 却得到 HTML（登录页 / 防盗链拦截页）时自动补救。
- **怎么配**：开关，默认开。需已安装 yt-dlp 组件才会生效。
- **效果**：检测到返回内容不是 `#EXTM3U` 而是 HTML 特征时，自动改用 yt-dlp 重抽直链；未装 yt-dlp 时保持明确报错。
- **示例**：站点对无 Cookie 请求返回登录页 → 自动切 yt-dlp 重试。

## 九、下载后处理

### 下载后 remux 为 MP4 `remuxToMp4`

- **作用**：把下载产物无损转封装为 `.mp4`。
- **怎么配**：开关，默认开。**需安装 ffmpeg 组件**。
- **效果**：核心 HLS 引擎**已自带** TS→MP4 转封装（失败时保留 `.ts`），此项是**兜底** —— 仅当核心 remux 失败、或产物来自非 HLS 任务（如 yt-dlp 抽出的 `.mkv`/`.webm`）时用 ffmpeg 补转一次；产物已是 `.mp4` 则**直接跳过**，不会双重转封装。
- **示例**：yt-dlp 委派得到 `.webm` → 开启后自动补转为 `.mp4`。

### 音视频合并失败兜底 `fixMuxFallback`

- **作用**：核心未能把视频与独立音轨合并（降级留下单独音频文件）时补做合并。
- **怎么配**：开关，默认开。**需安装 ffmpeg 组件**。
- **效果**：在 `onDone` 阶段检测到「有独立音轨且未被合并」时，用 ffmpeg `-c copy` 补做一次合并。
- **示例**：轨对任务结束后目录里出现视频文件 + 单独的音频文件 → 自动合并为一个文件。

## 十、订阅追更

把「分集列表页」加为订阅源（provider = `m3u8play`），插件每次刷新会：

1. 抓取该页；
2. 找出其中**一批同构的同站链接**（形态聚类取最大簇，按序号排序）；
3. 作为 feed 条目返回，交给引擎按 `guid` 去重建任务。

- 页面命中播放器标记（`<video>` / hls.js 等）时判定为单集页，返回**空 feed**（宁可空，不可把「上一集 / 下一集」当成两集推送）。
- 条目数默认至少 2 条才成立（比「自动识别剧集页」的 3 条宽松 —— 订阅地址是你主动配置的）。
- `guid` 由「主机 + 路径」算出，**刻意丢掉 query**，避免 CDN 签名抖动导致重复下载。
- 站点结构特殊时，用 **providerConfig**（JSON）兜底：

```json
{
  "minItems": 2,
  "maxItems": 200,
  "linkPattern": "vodplay/\\d+-\\d+-\\d+\\.html",
  "include": "第.*集",
  "exclude": "预告|花絮"
}
```

- 注意：预告 / 花絮的剔除**只按 URL 判断**，不看链接文字；站点若把预告做成正常路径，请用 `exclude` 手工排除。

> ⚠️ 订阅（`subscriptions`）目前**未列入 FluxDown 公开插件文档**，是按引擎实现接入的。若某次引擎升级后行为变化，请以引擎源码为准。

## 附录：文件名机制

下载成品名由**两端共同决定**，插件只能提供一半：

| 环节 | 谁负责 | 说明 |
| --- | --- | --- |
| `fileName` 建议值 | 插件 resolver | 决策链：`ctx.fileName`（已有名）→ 页面 `<title>` → URL 推导 |
| 最终文件名 | FluxDown 核心 | 插件给了就用；**没给则回落到「取 `<title>`，站点无 title 时用 `video`」** |

**为什么会出现满屏 `video`？** 站点播放页根本没有 `<title>`（或标题就叫「视频」），而任务在下载时又没走到插件的命名分支 —— 核心取不到 title 就回落 `video`。实测 `play.hhuus.com` 的播放页确实无 `<title>`，属此类。

**为什么会出现一堆 `index`？** 这些站的播放列表固定叫 `index.m3u8`，若直接取末段文件名会得到毫无区分度的 `index`。v1.4.0 起不再采用这类通用名。

**v1.4.0 的命名规则**（`src/resolver.js` 的 `nameFromUrl`）：

1. 文件名有信息量 → 直接用（`EP01_1080p.m3u8` → `EP01_1080p`）
2. 文件名是 `index`/`playlist`/`master` 等 → 向上找**第一个 ID 段**（`.../298d923ea9c3/index.m3u8` → `298d923ea9c3`）
3. 再不行 → 取上层非通用目录名（`.../play/mepljmpe/index.m3u8` → `mepljmpe`）
4. 全无可用信息 → `video`

再叠加默认模板 `{title} {host}`，最终形如 `298d923ea9c3_bfeng11.com`、`mepljmpe_play.hhuus.com`。

**同一站点多集名字一样怎么办？** 用模板塞入更多区分位，例如：

```
nameTemplate = {title} {date}       # 加下载日期
nameTemplate = {title} {res} {host} # 加画质与域名
```

**仍然叫 `video` 的两种硬限制**（插件无法突破）：

1. **下载时不会调用插件 resolver**：若在画质框里选「忽略插件重试」，或该链接被核心缓存复用，插件这次拿不到执行机会，给不出 `fileName` —— 只能手改文件名，或关掉「自动选择」后重下以确保走插件路径。
2. **弹画质框的手选模式下部分情况不返回文件名**：此时文件名由核心决定，插件只在「自动选择」或直接返回 media playlist 时给 `fileName`。

**排查建议**：打开插件日志看是否有
`[m3u8-resolver] 页面无 <title>，无法取出片名；改用 URL 推导` —— 出现即说明该站点页面本身没有标题，命名只能靠 URL 推导。
